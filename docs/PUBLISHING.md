# Публикация проекта

## Репозиторий

Назначение: [github.com/lazar2606/tiny-ru](https://github.com/lazar2606/tiny-ru).
В папке подготовлены исходники, готовые программы, данные, три необходимых
чекпоинта, отчёты и уведомления о лицензиях. Временные сборки и дистрибутивы
компиляторов не входят в набор публикации.

Перед первым коммитом из корня репозитория:

```sh
git status --short
git remote -v
git add .
git diff --cached --stat
git commit -m "Tiny-RU 2.1r3: исходники и сборки DOS/Windows"
git push -u origin main
```

Удалённый `origin` должен указывать на `https://github.com/lazar2606/tiny-ru.git`.
Имя и почту автора коммита задайте в своей конфигурации Git. Токены доступа
и пароли в файлы проекта добавлять не нужно.

Готовые EXE и BIN намеренно включены: читатель может запустить модель сразу
после получения проекта. Из `.pt` отслеживаются только финальный чекпоинт и
два начальных снимка; новые результаты обучения исключены через `.gitignore`.
Скрипты оболочки должны храниться с исполняемым битом, окончания строк задаёт
`.gitattributes`. У данных и бинарных весов сохраняются исходные байты.

## Файлы для релиза

После проверки текущих файлов можно создать архивы:

```sh
mkdir -p dist
python3 scripts/package_release.py
python3 scripts/package_windows.py
python3 scripts/package_source.py
```

В релиз можно приложить `tiny-ru-windows.zip`, `tiny-ru-dos.zip`,
`TINY-RU.IMG` и `tiny-ru-source.zip`. Каталог `dist/` исключён из Git,
чтобы архивы не дублировали исходники в истории.
Образ дискеты содержит файлы приложения; загрузочная DOS в него не входит.
Скрипт упаковки Windows сверяет измерения и сведения о сборке из `reports/windows/`.

После создания релиза добавьте его настоящую ссылку в README. Для этого
выпуска ссылка на скачивание указывается после загрузки файлов в релиз.
